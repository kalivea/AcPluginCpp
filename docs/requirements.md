# AcPluginCpp 改进需求

## 范围与基线

本项目是 Windows C++ / ObjectARX / MFC 插件集合，包含通用数据库工具、梁柱自定义实体、轴网、反应器和界面模块。按四个阶段推进；每阶段在上一阶段的契约与验证基础上实施。

保留既有命令和有效的版本 1 DWG 字段布局。稳定性修复允许增加返回 `Acad::ErrorStatus` 的接口及兼容包装，不以修复为由增加新的建模功能。

## 第一阶段：稳定性修复

目标：修复内存所有权、重复关闭、DWG 反序列化和错误处理，统一 `Acad::ErrorStatus` 返回规范。

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| S1-01 | 明确临时对象、数据库对象与借用别名的所有权 | 临时对象在所有退出路径释放；成功打开的句柄只关闭一次；cast 别名和借用参数不被独立释放 |
| S1-02 | 入库、打开、迭代、复制、样式与 DWG 导入错误安全退出 | 不解引用失败输出；输出 ID 初始化为空；返回第一个操作错误；兼容接口说明所有权 |
| S1-03 | 梁柱与辅助对象防御性 DWG 读取 | 检查版本、计数、有限数值、枚举与数组一致性；SDK 字符串正确释放；重复读取不累积；读取失败不提交半成品自定义数据 |
| S1-04 | 统一错误规范 | 可失败底层接口返回 `Acad::ErrorStatus`；成功为 `eOk`；参数错误为 `eInvalidInput`；未知版本为 `eMakeMeProxy`；SDK 错误原样传播；命令/UI 报告失败 |
| S1-05 | 提供可重复的阶段验证 | 回归覆盖异常输入、截断、重复读取、成功/失败清理；使用本地 SDK 编译；报告实际执行与待执行的 CAD 验证 |

边界：不变更 DWG 版本，不重组 DLL，不统一全工程属性表。编译时可临时指定本机 SDK 和工具集以验证源代码；这不替代第三阶段的正式兼容支持。

## 第二阶段：架构整理

目标：明确几何算法、构件参数数据、ObjectARX 数据库适配、MFC 界面四层，减少直接依赖。

- 几何层只处理数学对象和算法，不访问工作数据库或 MFC 控件。
- 参数层管理构件参数与校验，独立于界面与数据库对象的生命周期。
- 数据库适配层负责实体创建、持久化、选择、事务及错误传播。
- UI 层读取/显示参数、调用应用操作并报告结果，避免直接实施几何和数据库流程。
- 交付依赖图、接口迁移与层级验证；保留现有功能和图纸兼容性。

## 第三阶段：工程化

目标：支持 AutoCAD 2026，统一 MSBuild 属性表，增加自动化编译和宿主回归。

- 统一 SDK、工具集、运行库、包含/库目录、输出与依赖配置，支持可覆盖的本地 SDK 根路径。
- 以 AutoCAD 2026 官方支持的工具链建立 Debug/Release x64 编译与加载验证。
- 自动化创建包含梁、柱、轴网和反应器的图纸，保存并重开，核对参数与几何。
- 对构件创建、编辑、删除执行 UNDO/REDO；在同图及跨图执行复制粘贴，核对实体类型、数据、引用与显示。
- 本机测试与 CI 输出可追踪日志；缺少 AutoCAD 的机器明确只完成编译或宿主无关检查。

## 第四阶段：增强结构建模能力

目标：引入稳定构件 ID、参数约束、梁柱关联更新、统一截面定义和模型导出接口。

- 稳定 ID 与临时 ObjectId 区分，定义新建、克隆、复制粘贴、保存/重开和跨图行为。
- 参数约束对交互修改、导入和持久化一致生效，失败保留已有有效模型。
- 梁柱关联更新定义引用完整性、删除行为和循环更新防护，支持 UNDO/REDO。
- 统一截面定义供几何、参数、数据库和 UI 使用，支持有版本的迁移。
- 模型导出提供稳定的数据契约、单位、截面与关联信息，附示例和验证。
